# Deploying the chat server

How to install the server on the KV260, choose which models it serves, and
share the FPGA with other jobs.  Everything here runs from the host with
`deploy.py`; the model guides cover building each model's library.

## Prerequisites

The chat server reuses the [`bert_squad/`](../../bert_squad/README.md) demo:
its config, its model and its generated project.  You need:

- **The BERT demo's config**, `demo/bert_squad/bert_squad_config.json`.
  `deploy.py` takes everything board-specific from it: ssh address and key,
  UIO device names, the driver directories, the weights directory and
  the board lock.
- **The driver sources** of VectorOPKernel, MatmulKernel and ConvKernel
  (`make driver_vectorop_rtl driver_matmul_rtl driver_conv_rtl`
  in `build/`).
- **The BERT model and `vocab.txt`.**  These are downloaded when missing:
  - `deploy.py` fetches `vocab.txt` before it touches the board;
  - generating the BERT project fetches the model (435 MB);
  - both go to the paths in the BERT config, through
    `../bert_squad/scripts/fetch_assets.py`, which can also fetch them ahead
    of time.
- **The libraries of the other models**, built and installed once on the
  board if you want to serve them.  See [Choosing the models](#choosing-the-models).

## Deploy, stop, status

```bash
cd demo/chat
cp chat_config.json.example chat_config.json   # defaults: port 8000, no API key, bert-squad only
PY=../../inference-scheduler/.venv/bin/python

$PY deploy.py                  # generate (if needed), weights, build, start, wait for /health
$PY deploy.py --status         # unit state + /health
$PY deploy.py --stop           # stop the server (frees the FPGA)
$PY deploy.py --hold           # start, keep the board lock, follow the log; Ctrl-C stops it
$PY deploy.py --check-only     # only check the board's prerequisites
$PY deploy.py --regenerate --plan   # regenerate the BERT project in planning mode first
                                    # (doc/plans/TACTICS_PLAN.md §9; or "plan" in the BERT config)
```

`deploy.py` prints the URL and a few example commands when the server is up.

## What `deploy.py` does

Steps, in order:

1. **vocab**: download BERT's `vocab.txt` if it is missing.
2. **project**: generate the BERT project with
   `demo/bert_squad/scripts/generate_project.py`.  This happens only when
   the project is missing or incomplete: no `bert_squad` library target, or
   no `test/bert_api.c` / `CMakeLists.txt` (a project generated by an older
   version of the BERT demo).  `--regenerate` forces it.
3. **preflight**: check the board over ssh.
   - **Checks that stop the deploy when they fail:** the BERT demo's checks
     (UIO devices and the rest), Python ≥ 3.8, and each configured model's
     library and tokenizer.  For the image and speech models also Pillow,
     numpy and espeak-ng.
   - **Reported for information only:** free CMA, `systemd-run`, a C
     compiler, and ffmpeg.
   - **A fix it applies.**  It installs
     `board/kv260/kv260-no-cpu-powerdown.conf` as
     `/etc/tmpfiles.d/kv260-no-cpu-powerdown.conf` when it is missing, and
     applies it at once.  That keeps the cores out of the PSCI core
     power-down idle state: a core parked there stops the token stream,
     and later SSH and ping (the board hangs of CHAT_PLAN §18).
4. **stop**: stop a running server (the new one replaces it).
5. **weights**: upload `weights/*.dat` to the BERT config's weights
   directory; only files whose size or SHA-1 changed are sent.
6. **build**: upload the project sources and build `lib/libbert_squad.so`
   on the board.  Skipped when the generated sources and the cmake options
   are unchanged since the last build.
7. **server**: upload the server files, `vocab.txt` and the tokenizers of
   the configured generative models, and build `lib/libsampler.so` from
   `src/sampler.c` (under a second; without a compiler the server samples
   in Python, slower but with the same tokens).
8. **start**: start the server, then wait until `GET /health` answers.
   Just before starting, it drops the board's page cache.  Cached file
   pages left in the CMA area by the uploads and the build can make a
   large model's contiguous allocation fail even though CmaFree looks big
   enough (TTS_PLAN §5).

**Where things go on the board.**  Everything is installed in `remote.dir`
of `chat_config.json` — `<dir>` below, by default `/root/kv260_chat/`:
- `project/`: the sources and the build;
- `lib/`: `libbert_squad.so`, `libsampler.so` and the other models'
  libraries;
- the server files and `vocab.txt`.

**How the server runs.**  By default as a transient systemd unit,
`kv260-chat` (`systemd-run`):
- it survives the ssh session and is not started at boot;
- it logs to `journalctl -u kv260-chat`;
- on SIGTERM it finishes the running request, then stops.

`server.launcher: "nohup"` runs a detached process instead, logging to
`<dir>/server.log`.

**Timing.**  The first deploy builds for about 16 s.  Startup takes 1.6 s
(`bert_open`: the pool buffer plus 217 MB of weights from the page cache).

## Choosing the models

`server.backends` in `chat_config.json` lists the backends to serve; the
first one is the default model.

```json
"backends": ["smollm2-360m", "smollm2", "bert-squad", "smolvlm", "piper"]
```

(This is the board's setup: all five models, SmolLM2-360M the default.)

| Backend | Needs on the board | Built by | Config block |
|---|---|---|---|
| `bert-squad` | `lib/libbert_squad.so` | `deploy.py` itself | the BERT demo's config |
| `smollm2` | `lib/libsmollm2.so`, `/root/smollm2_weights` | [`llm_board.py --install-only`](SMOLLM2.md#install-smollm2-135m) | `smollm2` |
| `smollm2-360m` | `lib/libsmollm2_360m.so`, `/root/smollm2_360m_weights` | [`llm_board.py --install-only`](SMOLLM2.md#smollm2-360m-instruct) | `smollm2_360m` |
| `smolvlm` | `lib/libsmolvlm_256m.so`, `/root/smolvlm_256m_weights`, `python3-pil` | [`llm_board.py --install-only`](SMOLVLM.md#install) | `smolvlm` |
| `piper` | `lib/libpiper_tts.so`, `/root/piper_weights`, numpy, `libespeak-ng1` (ffmpeg for mp3 / opus / aac / flac) | [`tts_board.py --install-only`](TEXT_TO_SPEECH.md#install) | `piper` |
| `echo` | nothing (protocol only) | — | — |

- **Who builds the libraries.**  `deploy.py` builds only the BERT library.
  The others are built and installed by their own tools.  The preflight
  reports whether each is at its configured path: `smollm2.lib` (default
  `<dir>/lib/libsmollm2.so`), `smollm2_360m.lib`
  (`<dir>/lib/libsmollm2_360m.so`), `smolvlm.lib` and `piper.lib` likewise.
- **What `deploy.py` uploads for the generative models.**  It always uploads
  the text side (`smollm2_backend.py`, `smollm2_tokenizer.py`, `chatml.py`,
  `sampler.py`).  For each configured model it also uploads that model's
  `tokenizer.json` (the block's `tokenizer`, by default from the untracked
  `assets/<model>/`) to `<dir>/smollm2/`, `<dir>/smollm2_360m/` or
  `<dir>/smolvlm/`.
- **What the server receives.**  It gets each model's config block (`lib`,
  `weights_dir`, `model_id`, `tokenizer`, `cma_mb`) and `server.resident`.
  The `smollm2` block's sampling defaults apply to every generative model.
- **A library that fails to load.**  The server still starts with the other
  backends.  Requests for the missing model get 503 `model_not_loaded`.

## The FPGA and the board lock

**The running server owns the FPGA.**  Its process holds:
- **the loaded models' pool buffers:** one contiguous buffer per model for
  its weights and activations, in CMA, the memory region the FPGA kernels
  can address (sizes in the [table below](#several-models-on-one-fpga));
- **the kernels' UIO mappings:** the device files through which user-space
  programs drive the kernels' registers.

Nothing else may run kernels until the server is stopped.

**The board lock.**  Every board tool takes the same lock file,
`/tmp/kv260-board-<ssh.host>.lock`, unless `board_lock` names another
([REMOTE_TESTING §Board lock](../../../inference-scheduler/doc/REMOTE_TESTING.md#board-lock)).
- `deploy.py` holds it only while deploying, not while the server runs.
- To keep the board to yourself for as long as the server runs, use
  `--hold`.
- Before handing the board to another job, run `deploy.py --stop`.

## Several models on one FPGA

The board has 1000 MB of CMA (`cma=1000M`), and idle CmaFree was
626–813 MB, so the models' pools do not all fit at once.  Each model
declares the CMA it needs while loaded (`cma_mb`: its pool plus buffers and
a margin); the server uses it to decide what to evict.

| Model | Pool | `cma_mb` | Stays loaded (`--resident auto`) beside |
|---|---:|---:|---|
| BERT | 216 MiB | 224 | SmolLM2-135M, SmolVLM, Piper |
| SmolLM2-135M | 286 MiB | 330 | BERT, Piper; SmolVLM only when the CMA is not fragmented |
| SmolLM2-360M | 740 MiB | 760 | Piper only; swaps with the others |
| SmolVLM-256M | 495 MiB | 540 | BERT, Piper; SmolLM2-135M only when the CMA is not fragmented; swaps with SmolLM2-360M |
| Piper | 51 MiB | 55 | any other model, even SmolLM2-360M |

- **What is in a pool.**  SmolLM2-135M's, for example, holds one copy of
  every weight (decode reads the prefill image through MatmulKernel's GEMV
  path, MATMUL_OPTIMISATION §8b), the LM head, the KV caches and the
  intermediates.
- **Where to set it.**  The `cma_mb` values are the example config's
  (`smollm2.cma_mb`, ...); BERT's is fixed in its backend.

`--resident` (`server.resident` in the config) decides what stays loaded:

| Mode | Behaviour |
|---|---|
| `auto` (default) | The first backend loads at startup, the others too if CmaFree allows, else on their first request. Before a load, other models are evicted, least recently used first, while CmaFree < the new model's `cma_mb` + `--cma-margin-mb` (32). A load that still fails is retried once after evicting the rest. Models that fit together stay resident; the others swap. |
| `one` | At most one FPGA model; switching models unloads the other. A switch costs a load: BERT 1.6 s, SmolLM2 1.0 s with the weights in the page cache; cold from the SD card BERT 14.3 s, SmolLM2 35.6 s. |
| `all` | Everything loads at startup and stays (phase 1 behaviour). |

- **When loads happen.**  Loads and evictions run under the FPGA lock,
  between requests, so they never overlap inference.  The request that
  triggers a load logs `load=…ms`.
- **Watching it.**  `/health` shows `loaded` per model, `resident`,
  `cma_free_mb`, `loads` and `unloads`.
- **After an eviction** a generative model's prefix cache starts empty.


## Running the server by hand

For development, the server can be started on the board directly:

These are the flags `deploy.py` passes (`server_argv()` in `deploy.py`
builds them from `chat_config.json`); `python3 kv260_chat_server.py --help`
lists them all.

```bash
# BERT only
python3 /root/kv260_chat/kv260_chat_server.py --bert-lib /root/kv260_chat/lib/libbert_squad.so \
    --bert-weights /root/bert_squad_weights --vocab /root/kv260_chat/vocab.txt [--api-key KEY]

# both SmolLM2 sizes and BERT
python3 /root/kv260_chat/kv260_chat_server.py --backend smollm2 --backend smollm2-360m \
    --backend bert-squad --llm-lib /root/kv260_chat/lib/libsmollm2.so \
    --llm-sampler-lib /root/kv260_chat/lib/libsampler.so \
    --llm-tokenizer /root/kv260_chat/smollm2/tokenizer.json --llm-cma-mb 330 \
    --llm-360m-lib /root/kv260_chat/lib/libsmollm2_360m.so \
    --llm-360m-tokenizer /root/kv260_chat/smollm2_360m/tokenizer.json --llm-360m-cma-mb 760 \
    --bert-lib /root/kv260_chat/lib/libbert_squad.so --bert-weights /root/bert_squad_weights \
    --vocab /root/kv260_chat/vocab.txt [--resident auto|one|all]
```

Stop the unit first (`deploy.py --stop`): only one process may own the
FPGA.

## Without the FPGA

The server also runs on any machine without the FPGA, for testing clients
and the protocol:

```bash
# the protocol only: repeats the last user message, word by word
python3 demo/chat/kv260_chat_server.py --backend echo --port 8001
# the SmolLM2 backend with a scripted reply (no numpy needed)
python3 demo/chat/kv260_chat_server.py --backend smollm2 --llm-fake scripted --port 8001
# the real SmolLM2 model in float on the host (numpy + the safetensors weights; ~10 tok/s on 8 cores)
.venv-export/bin/python demo/chat/kv260_chat_server.py --backend smollm2 --llm-fake float --port 8001
```

`--llm-fake float` runs `scripts/llm_study.py`'s float64 reference model
behind the library's interface (`tests/fake_llm.py`).  Its greedy answers
equal transformers' ([Development](DEVELOPMENT.md#host-validation)).
